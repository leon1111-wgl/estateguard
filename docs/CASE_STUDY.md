# 案例：把一班重复告警整理成可交接的社区事件

## 一班工作里真正的困难

这是一个原创模拟小区，不是客户访谈或真实部署记录。

早班时，A 栋住户预约搬家。柜体经过客梯，连续四条记录都提示“大件进入”；同一过程中又出现推车挡门。车库入口的配送车辆产生五条通道占用记录，后门暗光镜头只给出低分线索。

如果只列出检测分数，值班员仍要自己回答：是不是同一事件？是否有例外？证据够不够？谁处理到了哪一步？这也是本项目从单个检测模块延伸到工作流的原因。

## 从需求到实现

| 痛点 | 设计 | 能检查的结果 |
| --- | --- | --- |
| 同一件事重复提醒 | 按摄像头、区域、类别、匿名轨迹和时间窗合并 | 不同车辆/镜头不能因时间接近而合并 |
| 正常搬家可能被误判 | 预约声明只作用于大件类别，仍需人工核对 | 预约不会自动豁免挡门和碰撞疑点 |
| 暗光告警分数低 | 高风险类别保留在证据不足队列 | 不用一条分数阈值隐藏所有风险 |
| 单帧不足以判断停车 | 区分物体检测与视频采样轨迹；设置持续时长规则 | 单张照片不能产生停车时长结论 |
| 交接缺乏依据 | 保存源观察、规则、复核理由和时间历史 | JSON 可恢复，Markdown 可阅读 |
| 标注质量影响模型 | 检查重复、时间区间、标签分歧、视频级跨集合泄漏 | 报告问题并保留人工裁决，不自动制造真值 |

## 实际 AI 链路

本地图片/短视频 → SSDLite MobileNet V2 → 类别、检测框与分数 → 简单 IoU 关联的匿名轨迹 → 用户指定的区域/停留/方向规则 → 候选事件 → 人工复核 → 导出交接。

模型权重与运行库由本站自托管。跟踪使用可复查的基线，并不是长期身份跟踪；跨遮挡、交叉目标和移动镜头可能关联错误，因此规则输出始终是待核实线索。

COCO 中没有“客梯违规”“损坏电梯”“乱扔垃圾”这些标签。现版本可以检测车辆、人以及部分家具、行李箱，再由场景规则组织候选；复杂行为需要领域标注、专门模型与独立验证。

## 当前测到了什么

固定合成班次：36 条观察、9 个参考事件。

| 事件级指标 | 逐条分数告警 | 场景规则与合并 |
| --- | ---: | ---: |
| 待办条目 | 33 | 9 |
| 匹配参考事件 | 7 | 8 |
| 未匹配 / 重复条目 | 26 | 1 |
| 漏掉参考事件 | 2 | 1 |

参考事件采用同摄像头、区域、类别、匿名轨迹，时间 IoU ≥ 0.1，重叠从高到低一对一匹配。重复记录会形成额外未匹配条目。新队列还额外保留低分高风险提示，因此结果体现整个流程改变，不能单独归因于合并算法。

保留两个不完美案例：柜体接近内壁不等于造成损坏；后侧垃圾满溢没有任何检测输入，后处理不可能凭空发现。没有真实业务试点，就不写“事故减少”“损耗降低”或“节约多少人力”。

## 一轮找茬带来的修复

独立审查模拟交接：导入大批次 → 记录复核 → 导出 → 新班次重新导入。它发现合法 3.28 MB 输入因重复序列化膨胀到 9.58 MB，超过自身导入上限。修复后去掉可重算事件副本，统一容量契约，成功恢复 6,000 条记录。

另外修复切换事件丢草稿、跨日期时间看起来一样、非法日期静默归一化。它们比新增装饰图表更直接影响使用。

## 怎样继续证明价值

下一阶段需要有许可的真实社区视频，按摄像头/日期划分训练、验证和测试，覆盖夜间、遮挡、拥挤、预约搬运与正常清运。先测现有基线的漏检和每小时误报，再决定是否增加领域检测器、时序模型或视频语言模型。部署价值需要试点中的复核耗时、任务完成率和未决事件数据，不由合成结果推算。

## 真实公开数据延伸：车位巡检

值班员需要判断某个采样时刻哪些车位有车，并确认模型是不是把阴影、遮挡或车身局部看错。项目新增独立车位页，保留成熟工作台框架；以 CNRPark 真实历史图片替代仅靠合成事件讲故事。浏览器实际运行本项目训练的分类器，原图、标签、模型结果与人工备注各自保留，交班可恢复。

训练4,284张、验证1,275张，跨相机测试6,413张；正确率76.84%，多数类基线74.55%。1,134张占用图被错报为空闲是当前最需要解决的业务风险，因此结果用于巡检与复核实验，不能声称已经可靠指导停车或减少人工成本。完整1,485个错例可直接选取原图检查。下一轮改进有了明确的真实数据基线，见 [数据与训练](PARKING_DATA.md)。
