# EstateGuard · 社区智能巡检设计

## 产品目标

帮助物业值班员把重复、含糊的监控线索整理为可复核、可交接的事件。典型班次会同时遇到预约搬家、客梯挡门、通道停靠、暗光画面与垃圾问题；单个检测分数无法说明是否同一事件、有没有现场例外、是否需要补证据。

第一版采用中文工作台。用户选择飞书式中文业务工具风格：浅色导航、紧凑布局、明确的文字层级、统一控件和克制的状态色。用户已明确认可并固定当前版面；后续只做沿用组件的功能扩展和必要适配。英文版等流程成熟后增加。

本项目受既有安全监控经历启发，独立实现。合成班次与参考事件由项目原创；公开校车图片用于验证通用模型运行；CNRPark 真实车位裁剪用于独立占用分类器训练、跨视角测试与历史快照巡检。没有原单位视频、标注、模型或部署收益。

## 当前架构

应用使用无需构建的 HTML、CSS 与 ES 模块。浏览器与命令行共享纯 JavaScript 事件引擎；Python 标准库脚本检查标注一致性。Node.js 22+ 用于开发验证，Python 3.10+ 用于本地服务与标注 QA。

本站自托管 TensorFlow.js 4.22.0、COCO-SSD 2.2.3 与 SSDLite MobileNet V2 权重（18,034,528 字节）。图片或每秒一帧、最多 20 帧的视频采样进入真实模型；输出类别、框与分数，再通过简单 IoU 关联、用户指定区域、停留时间与方向规则形成候选。原始检测、参数和实测耗时可导出。

加载器按资源清单流式读取并检查大小与SHA-256，进度来自实际字节数。仅将8个公共运行脚本/模型文件写入带版本哈希键的CacheStorage；使用缓存前重新校验，损坏项单独重下。网络30秒无进展报超时；缓存操作等待最多2秒，失败则回退到网络，取消操作不等待底层存储完成。模型通过TensorFlow IO接口装载，保持原COCO-SSD预热和推理代码。网络读取强制绕过HTTP缓存，字节数按解码后的资源大小统计，不是压缩后的线路流量。加载/初始化与逐帧推理耗时分别导出；当前页再次分析复用内存模型，新增下载和初始化计为0。

这是通用物体模型与规则基线。挡门、碰撞损坏和垃圾行为没有专用模型验证；不能把候选当作已确认违规。当前未实施领域微调、蒸馏、量化或论文中的时序模型。模型边界见 [MODEL_CARD.md](MODEL_CARD.md)。

COCO-SSD 2.2.3 的本地可复现补丁只分离单帧后处理中的分数下限与 NMS IoU：重叠阈值固定为原默认 0.5，用户调分数不再改变同帧重叠框抑制范围。默认分数 0.5 与上游保持相同处理；检测报告记录补丁、分数、NMS、最大框数、片段起点和采样参数。模型权重与跨帧关联规则均不变。原始上游文件和许可保留，资源校验包含补丁重建检查。

页面读取资源清单时绕过 HTTP 缓存，并在加载任何运行脚本前核对后处理版本标识。清单与页面不一致即停止、保留素材供重试，避免实际运行旧版却导出新版参数；CacheStorage 仍按文件哈希隔离旧、新脚本。

另有独立的车位占用分类器：公开数据 → 帧级隔离划分 → NumPy 实际训练 → 自托管权重 → 浏览器像素特征与推理 → 车位复核。它不改变原检测器，也不会将正常占用注入违停队列。数据与结果见 [PARKING_DATA.md](PARKING_DATA.md)。

车位人工待办与模型分数分别计算。只有保存为空闲或占用才算人工确认；未保存、待复核、无法判断仍未完成，无法判断另外归入需补证据。进度和筛选使用同一状态规则，按摄像头、日期、时刻、车位的完整样本标识区分。编辑或尝试保存人工结论即暂停回放；保存并继续只选择当前快照内尚未确认的样本，失败时保留原选择与草稿，全部完成后留在当前时刻。导出保留人工结论和可重算的快照进度，恢复时重新统计，不信任导入的进度数字。

## 主要工作流

1. 选择本地图片/视频或公开图片示例，检测物体。生成事件候选前，填写来源和素材实际时间、配置关注区域并明确核对。
2. 将候选送入复核队列；也可导入外部观察 JSON 或使用明确标记的合成班次。
3. 检验输入，按摄像头、区域、类别、匿名轨迹和时间间隔合并兼容观察。
4. 保留紧急、不确定线索，核对预约例外，查看本地证据并记录人工处置理由。
5. 导出输入、规则、决策与历史；通过重新导入恢复工作区，另导出中文交接单。

支持导入复核的八类事件是：大件搬运、挡门、碰撞疑点、违停、通道占用、逆行、垃圾乱放与满溢。它们是待核实的事件类别，不是自动责任判断。搬运预约只能影响大件类别，不能豁免挡门、碰撞或通道占用。

## 数据与正确性约束

- 输入含版本、名称、来源说明和观察列表。每条观察必须包含 ID、摄像头、区域、匿名轨迹、类别、带时区的时间、分数、质量、描述及证据标签。字段细节见 [DATA_CONTRACT.md](DATA_CONTRACT.md)。
- 时间必须是真实日历日期。观察时长采用区间并集，不把采样空隙或重叠重复计算为连续观察。
- 不同摄像头、轨迹、类别或区域不合并；匿名轨迹是上游数据范围内的对象标识，不是住户身份。
- 模型候选统一要求人工核对。低质量或无证据不能变成高把握结论；高风险类别的证据不足项仍留在队列。
- 人工确认待处理或待补证据，须覆盖原规则例外或低分分流。重新打开事件保留历史；非未处理状态必须填写理由。
- 原始 JSON 批次上限 5 MiB，工作区上限 32 MiB、10,000 条观察。本地媒体上限 100 MB。导入失败必须保持旧状态。
- 用户文本按文字渲染，证据标签不会触发网络请求。切换素材采用独立解码对象与请求序号，防止旧异步结果覆盖新文件。成功解码并准备画面后才提交新素材；损坏文件或过期请求不清除旧报告、现场信息与确认状态。加载期间暂时禁用分析、送审和导出，失败后恢复。
- 素材提交版本与异步请求序号分开。成功换素材清空来源/区域名/起始时间，片段起点归零，ROI 恢复整幅，并撤销确认。规则候选要求本次提交版本和来源、区域、ROI、时间、片段起点、规则、方向均与确认快照相同；改变分数或停留阈值不要求重复核对现场。
- 「沿用上次现场设置」只复制上次已明确核对的来源、区域名、规则、方向、停留阈值与 ROI；不带入时间或片段起点。只有原始宽高完全一致才允许复制 ROI，显示时缩放后的尺寸不作为依据。相同尺寸仍需人工核对，同尺寸不证明同摄像头。设置只在当前标签页内存中保留。
- 素材时间默认未知，不使用页面当前时间或文件修改时间代替。通用物体检测允许时间为空且不生成候选；规则分析要求用户输入有效日历时间，按 UTC+8 解析。勾选确认只记录用户已核对，不验证其输入是否符合拍摄事实。ROI 折叠摘要始终显示当前范围。
- 状态保留在当前标签页内存，按事件保存未提交草稿。关闭前必须导出；媒体不随工作区保存。没有自动上传、后端、账户、统计埋点或付费 API。

## 评测边界

停车错例审查使用冻结模型的完整公开预测，按错误类型、摄像头和车位筛选，默认保留全部错例。车位漏判比例以该车位原始占用标签数为分母，不能用错例集中度推断原因。离线清单和本次浏览器推理分开：前者只提供定位及可复查来源；选择错例后，后者重新读取实际像素，读取失败保持未分析，不回填离线分数。

车位人工确认空闲/占用前，必须成功显示当前样本的原图；原图失败允许保存待复核或带理由的无法判断，导出单独记录证据读取失败。原图与模型输入是不同文件，因此两者的失败状态分开。导入历史人工记录不证明本次看过原图；如重新保存明确结论，同样检查当前原图。手机从错例跳转后定位选中车位和复核区，异步推理完成不得把用户后来选择的样本拉回。

固定合成班次比较逐条分数告警与场景规则队列，使用相同输入和分数门槛。匹配要求摄像头、区域、类别、轨迹相同，时间 IoU ≥ 0.1，按重叠从高到低一对一匹配。报告条目数、匹配、未匹配、漏检与紧急不确定项。

队列缩减不等于视觉精度提升或人工耗时降低。保留已知误报和没有观察输入的漏检。真实模型的运行烟雾测试与这套合成流程结果分开记录；公开图片和重复图片生成的短片不能证明社区领域准确率。

## 研究与迭代

官方电梯和消防资料提供场景背景；Anomize、场景特定异常检测、CSI-VAD 等资料用于比较上下文与时序建模思路。记录查阅范围、来源日期和采用理由，不宣称复现其模型。详见 [RESEARCH.md](RESEARCH.md)。

由本地定时任务继续迭代：独立用户找茬代理复现工作流问题，独立界面设计师检查实际桌面与手机截图，每轮解决有证据支撑的问题并验证。发布到独立 GitHub 仓库和 Pages，在个人主页添加入口。没有在线自主代理或外部消息发送。
