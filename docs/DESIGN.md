# EstateGuard · 社区智能巡检设计

## 产品目标

帮助物业值班员把重复、含糊的监控线索整理为可复核、可交接的事件。典型班次会同时遇到预约搬家、客梯挡门、通道停靠、暗光画面与垃圾问题；单个检测分数无法说明是否同一事件、有没有现场例外、是否需要补证据。

第一版采用中文工作台。用户选择飞书式中文业务工具风格：浅色导航、紧凑布局、明确的文字层级、统一控件和克制的状态色。用户已明确认可并固定当前版面；后续只做沿用组件的功能扩展和必要适配。英文版等流程成熟后增加。

本项目受既有安全监控经历启发，独立实现。合成班次与参考事件由项目原创；公开校车图片用于验证通用模型运行；CNRPark 真实车位裁剪用于独立占用分类器训练、跨视角测试与历史快照巡检。没有原单位视频、标注、模型或部署收益。

## 当前架构

应用使用无需构建的 HTML、CSS 与 ES 模块。浏览器与命令行共享纯 JavaScript 事件引擎；Python 标准库脚本检查标注一致性。Node.js 22+ 用于开发验证，Python 3.10+ 用于本地服务与标注 QA。

本站自托管 TensorFlow.js 4.22.0、COCO-SSD 2.2.3 与 SSDLite MobileNet V2 权重（18,034,528 字节）。图片或每秒一帧、最多 20 帧的视频采样进入真实模型；输出类别、框与分数，再通过简单 IoU 关联、用户指定区域、停留时间与方向规则形成候选。原始检测、参数和实测耗时可导出。

加载器按资源清单流式读取并检查大小与SHA-256，进度来自实际字节数。只把资源清单中登记的公共运行脚本与模型文件（随所用模型而定，例如检测、车位编码器与 ONNX 运行库）写入带版本哈希键的CacheStorage；使用缓存前重新校验，损坏项单独重下。网络30秒无进展报超时；缓存操作等待最多2秒，失败则回退到网络，取消操作不等待底层存储完成。模型通过TensorFlow IO接口装载，保持原COCO-SSD预热和推理代码。网络读取强制绕过HTTP缓存，字节数按解码后的资源大小统计，不是压缩后的线路流量。加载/初始化与逐帧推理耗时分别导出；当前页再次分析复用内存模型，新增下载和初始化计为0。

2026-10-19 起默认检测器为 D-FINE-N：官方 COCO 权重由本项目导出为 fp32 ONNX，经 `web/detector-dfine.mjs` 在 ONNX Runtime Web 单线程 WASM 中运行，输出与 COCO-SSD 同形的框、类别和分数，所以轨迹关联、区域、停留、方向规则和送审流程不变。SSDLite 保留可选，检测报告记录所用检测器、后处理（`dfine-topk-v1` 或 `coco-ssd-2.2.3-fixed-nms-v1`）、分数下限与耗时。ONNX Runtime 由 `web/ort-runtime.mjs` 从校验后的字节导入，页面内的检测器与车位 DINOv2 共用一个实例。默认与分数下限来自 COCO val2017 上预先固定的协议，见 [detector-upgrade-protocol.md](validation/detector-upgrade-protocol.md)；链接参数 `?detector=` 可固定检测器。

这是通用物体模型与规则基线。挡门、碰撞损坏和垃圾行为没有专用模型验证；不能把候选当作已确认违规。当前未实施领域微调、蒸馏、量化或论文中的时序模型。模型边界见 [MODEL_CARD.md](MODEL_CARD.md)。

视频停车规则从同一车辆轨迹的每次区域访问中提取稳定片段。至少 3 个采样、相邻采样间隙不超过 1.6 秒，片段内归一化中心最大两两距离不超过 0.06，且达到用户设定时长才生成候选。未达时长的窗口遇到位移冲突时向前滑动，避免驶入阶段永久否决后续停稳；已达标的窗口在位移冲突、丢检或出区域时结束。只从该段计算起止、分数与证据。规则版本及数值写入检测报告，不改模型权重。

每个停车稳定段具有独立 `stable_segment_id`，同轨迹所有区域访问统一编号。事件引擎把它加入合并条件，避免两次短停在下游被叠加跨过停车宽限期；匿名 `track` 保持原目标身份。旧观察不含此字段时保留原合并规则，不能追溯恢复旧报告已经丢失的分段。每秒采样和简单 IoU 跟踪仍可能受遮挡、串号、相机运动或极慢移动影响；稳定片段只是待人工核对的线索，不证明连续停车。

COCO-SSD 2.2.3 的本地可复现补丁只分离单帧后处理中的分数下限与 NMS IoU：重叠阈值固定为原默认 0.5，用户调分数不再改变同帧重叠框抑制范围。默认分数 0.5 与上游保持相同处理；检测报告记录补丁、分数、NMS、最大框数、片段起点和采样参数。模型权重与跨帧关联规则均不变。原始上游文件和许可保留，资源校验包含补丁重建检查。

页面读取资源清单时绕过 HTTP 缓存，并在加载任何运行脚本前核对后处理版本标识。清单与页面不一致即停止、保留素材供重试，避免实际运行旧版却导出新版参数；CacheStorage 仍按文件哈希隔离旧、新脚本。

另有独立的车位占用分类器：公开数据 → 帧级隔离划分 → NumPy 实际训练 → 自托管权重 → 浏览器像素特征与推理 → 车位复核。它不改变原检测器，也不会将正常占用注入违停队列。数据与结果见 [PARKING_DATA.md](PARKING_DATA.md)。

2026-10-17 起车位巡检有三种可选占用模型，均只用 CNRPark A 训练：原 MLP32 基线、复用检测器骨干的 MobileNetV2 迁移头、以及 DINOv2-small 线性探针（默认）。两个迁移模型冻结编码器，只训练 1,281 / 769 个参数的线性头；编码器资源经同一个校验加载器读取并缓存。DINOv2 使用自托管 ONNX Runtime Web 1.30.0 的单线程 WASM 和 int8 模型，输入 112×112（按单线程延迟预算选择）。离线特征由浏览器调用同一网页模块提取，页面与离线特征逐位一致；协议见 [validation/parking-transfer-protocol.md](validation/parking-transfer-protocol.md)。

迁移模型输出经温度校准的占用概率，再按“自动判空闲 / 自动判占用 / 需人工复核”分流。阈值只能来自同一摄像头已保存的人工结论，并须按“车位·日”计数、覆盖至少 2 个日期，用 Learn then Test（Clopper–Pearson 上界、Bonferroni）检验错误比例不超过所选目标；离线回放显示通过检验的空闲侧阈值到后续季节仍多数超标，所以检验结果只描述校准数据。阈值启用后，约 10% 的“车位·日”按标识哈希随机抽中，其中的自动判定改送人工并标为「抽检」；按车位·日累积抽检出错，单侧似然比序贯检验（备择为目标 2 倍）证据足够时自动撤销该侧阈值，抽检车位保存结论前不显示模型概率；撤销记录按摄像头保存并随导出、恢复保留，之后任一模型只能用撤销日期以后的人工结论重新校准（[协议附录 5](validation/parking-transfer-protocol.md)）。EXT 回放中它没有误撤销，但 3 个超标阈值只撤销了最严重的 1 个，而且在错误集中出现约 3 天后才撤销；训练视角上的阈值不直接用于新摄像头，未证明时全部送人工。值班员也可用本相机人工结论做 L2-SP 少样本自适应；自适应用过的结论不能再用于校准，自适应或改风险目标后原阈值作废。模型分数、校准、自适应都按模型与摄像头分开保存，导出时记录。数据集标注从不参与在线校准或自适应。

车位人工待办与模型分数分别计算。只有保存为空闲或占用才算人工确认；未保存、待复核、无法判断仍未完成，无法判断另外归入需补证据。进度和筛选使用同一状态规则，按摄像头、日期、时刻、车位的完整样本标识区分。编辑或尝试保存人工结论即暂停回放；保存并继续只选择当前快照内尚未确认的样本，失败时保留原选择与草稿，全部完成后留在当前时刻。导出保留人工结论和可重算的快照进度，恢复时重新统计，不信任导入的进度数字。

车位模型输入失败按模型键与完整样本标识保存，列表、详情、完成提示均读取对应模型的状态；成功重试只清除该模型该样本的失败。单样本推理失败同时删除其旧分数、校准分数和冻结特征，避免自适应或重置时从旧特征重建一个已经标为失败的结果。没有尝试的样本沿用已有状态，停止不清空其他模型的结果。复核原图可读性仍独立按样本判断，不因某个模型输入失败而否定可见的原图。

本地单车位图片采用独立任务状态与成功结果区。加载进度、中文错误及取消不改上次成功结果；新图完成真实推理后才一次替换图片、文件名与模型分数，并回收旧图片 URL。失败或取消只释放本次临时资源。空文件变更不改变当前任务，取消后迟到的结果不提交。

车位本地图片与公开快照推理互斥，期间禁止切模型、再选文件或启动另一分析；本地分析期间保留公开快照浏览、人工复核及导出。错例跳转也先检查本地任务，不能绕过互斥。取消会中止对应模型的下载；共享核心配置仅取消本地任务的等待，页面初始化可继续。已经开始且无法中断的解码或模型计算需结束后才解锁，期间明确提示正在取消；不宣称可立即打断 WASM。各模型加载控制器分别保存，防止停止取消其他模型。交班恢复仍在任务未结束时拒绝，其提示不被本地下载进度覆盖。

车位 JSON 的 `failures` 对应当前 `prediction_model`，新增的 `failures_by_model` 与 `predictions_by_model` 使用相同模型键；两个字段均记录本标签页实际运行情况。新字段是版本 1 的附加诊断信息，恢复人工记录时不采用文件中的失败、分数或特征；旧文件缺少该字段仍可恢复。模型运行报错的清单不是现场违规结论，也不证明样本本身损坏。

车位交接文件另存版本为 1 的 `view`：快照标识、所选车位、模型及其 SHA-256、筛选、标注开关。恢复时校验快照来自已加载的公开数据、车位属于该快照、模型版本可用且与旧元数据一致，再一次性应用人工结论、位置和合并后的抽检撤销限制。模型相关筛选改为全部车位并解释需重新分析；人工筛选若隐藏交接车位，也回到全部并说明。旧文件有 `source_frame` 时返回该快照首个有记录的车位；完全没有位置的旧文件保留本页位置并提示。

导入在读取前和异步读取后检查推理/上传状态，分析中拒绝恢复；所有输入校验和撤销记录合并先在临时状态中完成，失败不改本页记录、草稿、视图或已有撤销限制。成功应用时停止回放，较早文件的迟到读取不能覆盖后选文件。导入不自动加载编码器、不信任文件分数或阈值，原有现场自适应和阈值清除后需重新设置；本页已经实际运行的基础模型结果仍可保留。

## 主要工作流

1. 选择本地图片/视频或公开图片示例，检测物体。生成事件候选前，填写来源和素材实际时间、配置关注区域并明确核对。
2. 将候选送入复核队列；也可导入外部观察 JSON 或使用明确标记的合成班次。
3. 检验输入，按摄像头、区域、类别、匿名轨迹和时间间隔合并兼容观察。
4. 保留紧急、不确定线索，核对预约例外，查看本地证据并记录人工处置理由。
5. 导出输入、规则、决策与历史；通过重新导入恢复工作区，另导出中文交接单。

支持导入复核的八类事件是：大件搬运、挡门、碰撞疑点、违停、通道占用、逆行、垃圾乱放与满溢。它们是待核实的事件类别，不是自动责任判断。搬运预约只能影响大件类别，不能豁免挡门、碰撞或通道占用。

## 数据与正确性约束

- 输入含版本、名称、来源说明和观察列表。每条观察必须包含 ID、摄像头、区域、匿名轨迹、类别、带时区的时间、分数、质量、描述及证据标签。字段细节见 [DATA_CONTRACT.md](DATA_CONTRACT.md)。
- 时间必须是真实日历日期。观察时长采用区间并集，不把采样空隙或重叠重复计算为连续观察。
- 不同摄像头、轨迹、类别、区域或停车稳定片段不合并；匿名轨迹是上游数据范围内的对象标识，不是住户身份。
- 新事件在起点并列时按观察 ID 的固定 UTF-16 码元顺序确定编号，最终队列同样不使用浏览器语言排序。恢复版本 1 的旧交班时，按每个时间分段的成员和最早时刻校验历史编号；唯一合法旧编号原样沿用，不迁移人工记录。不同编号指向同一事件、非最早成员或未知成员的历史均拒绝，决策仍须与最后一条历史完全一致。应用规则并明确清空历史后，使用新的稳定编号。规则调用使用 `buildEvents`；处理已保存复核的渲染、保存、恢复统一使用 `buildWorkspaceEvents`。
- 模型候选统一要求人工核对。低质量或无证据不能变成高把握结论；高风险类别的证据不足项仍留在队列。
- 已保存的人工待复核、确认待处理或待补证据，均覆盖原规则例外、低分或短观察分流；最新的已排除或已处理结论退出待办。没有人工记录时的默认待复核，以及尚未保存的草稿，都不覆盖规则。徽标优先显示已保存人工状态，规则原因仍保留供核对；导出恢复使用原审查历史，不重写规则路由。重新打开事件保留历史，所有保存操作必须填写理由。
- 原始 JSON 批次上限 5 MiB，工作区上限 32 MiB、10,000 条观察。本地媒体上限 100 MB。导入失败必须保持旧状态。
- 事件复核附件先在独立媒体对象中解码，图片有效或视频首帧与时长可读后才替换。读取失败、取消、超过 10 秒或过期请求均保留旧附件；按事件隔离请求，替换整个工作区时取消全部旧请求，即使事件 ID 重复也不复用。读取时保留预览 DOM 和草稿，只暂停该事件保存；切换事件仍可操作。模型候选引用同一素材时只解码一次，并在最后一个引用释放后撤销地址。页面说明只验证可打开，不验证素材与事件的事实对应；媒体仍不进入导出 JSON。
- 用户文本按文字渲染，证据标签不会触发网络请求。切换素材采用独立解码对象与请求序号，防止旧异步结果覆盖新文件。成功解码并准备画面后才提交新素材；损坏文件或过期请求不清除旧报告、现场信息与确认状态。加载期间暂时禁用分析、送审和导出，失败后恢复。
- 分析中途失败时，至少有一个完成采样帧才保留失败报告；原始框与成功帧逐项对应，未完成帧不计入耗时均值或成功计数。报告区分完成、停止与失败，失败位置使用相对素材时间；停止和失败都不生成候选。轨迹或规则派生失败也保留原始帧，不重新执行已失败的派生步骤；无法整理轨迹时明确显示未完成。画布恢复最后成功画面及其检测框、采样时间，避免失败帧像素与前帧框混用。复核工作区不受影响，素材和设置保留供从原起点重试，不提供断点续跑。
- 事件工作区的模拟班次与 JSON 读取采用最新请求优先；较新读取即使失败或取消，旧请求也不能再提交。每次成功替换工作区（含应用规则和模型候选送审）统一使旧读取失效，过期成功和错误均不改记录或提示。模拟班次准备并校验完成后才检查当前未导出状态，因此等待期间新写的草稿或人工结论也受替换确认保护。取消或读取失败保留当前记录、草稿、策略与附件；读取中仍可复核，状态沿用现有消息区。这不是后台自动保存或多人冲突合并。
- 素材提交版本与异步请求序号分开。成功换素材清空来源/区域名/起始时间，片段起点归零，ROI 恢复整幅，并撤销确认。规则候选要求本次提交版本和来源、区域、ROI、时间、片段起点、规则、方向均与确认快照相同；改变分数或停留阈值不要求重复核对现场。
- 「沿用上次现场设置」只复制上次已明确核对的来源、区域名、规则、方向、停留阈值与 ROI；不带入时间或片段起点。只有原始宽高完全一致才允许复制 ROI，显示时缩放后的尺寸不作为依据。相同尺寸仍需人工核对，同尺寸不证明同摄像头。设置只在当前标签页内存中保留。
- 素材时间默认未知，不使用页面当前时间或文件修改时间代替。通用物体检测允许时间为空且不生成候选；规则分析要求用户输入有效日历时间，按 UTC+8 解析。勾选确认只记录用户已核对，不验证其输入是否符合拍摄事实。ROI 折叠摘要始终显示当前范围。
- 分析参数按用途启用：停留秒数只用于停车规则，预期方向只用于逆向规则，片段起点只用于视频。闲置控件保留草稿并禁用，附简短用途说明；不参与校验、现场确认或本次报告，相关字段导出为 `null`（图片起点为 0）。切回相应规则必须重新校验，图片误选视频规则先说明素材类型不适用。统一控制逻辑同时保留读取、推理期间的忙碌锁。沿用现场只恢复当时生效的参数，不能用 `null` 清掉当前其他规则的草稿。
- 每份完成或中断的检测报告生成一次独立 `analysis_id`，送审批次沿用该标识；重复点击不生成新标识。仅标识存在且验证后的完整批次与当前批次逐字序列化相同，才返回当前复核：使旧读取失效但保留政策、dirty、草稿、历史和附件，不重新挂载媒体。不同任务即使候选相同也正常替换；相同标识但不同批次内容同样不能复用。标识不是媒体校验、可信签名或跨任务去重依据。
- 成功替换工作区时清除旧场景筛选，有待办则显示待办，否则显示全部事件。失败或取消保持旧筛选；普通保存和切换事件不重置筛选。同任务返回保留有效筛选、选中项及 DOM，仅原筛选没有可见项时恢复有效视图。
- 新批次候选成功送审后，同步显示复核页、聚焦当前事件标题并定位详情起点。桌面与手机都从状态、来源、时间开始阅读；标题只接受程序焦点，不加入常规 Tab 顺序。无需等附件解码，后续媒体就绪不再定位。同任务返回、取消、失败不触发这次定位；未实现普通页面切换的阅读位置恢复。
- 保存复核成功后，只有当前选中 ID 改变才同步定位详情起点并聚焦新事件标题；当前筛选变空则聚焦现有空视图标题。保留原筛选与选择首个可见事件的规则，不按关闭状态猜测是否换项；因此「全部事件」中结案仍留在当前项，「已处理」中重开也能正确交接。普通同项保存、保存失败、手动筛选和附件解码不新增定位；不等待媒体、不安排延迟滚动，隐藏复核页时不抢焦点。新标题仅为程序焦点，Tab 继续进入证据/复核控件或空视图后的交接单按钮。其他事件的草稿和附件不因换项清除。
- 事件草稿按当前结论和备注与已保存值的差异判断；无人工结论时以待复核和空备注为基线。比较时只对齐输入框的 CRLF/CR→LF 换行与保存时的首尾空白裁剪，不改变导入的历史原文；内部空格、连续换行和结论变化仍为实际修改。改回原值即移除该事件草稿，不影响其他事件。未导出的工作区变化与草稿分别跟踪，替换、规则重置、离开保护取两者并集；撤回草稿不能清除已保存未导出的提醒。原队列草稿标记就地更新，不重绘表单或附件。显式保存仍作为一次人工审查追加历史。
- 状态保留在当前标签页内存，按事件保存未提交草稿。关闭前必须导出；媒体不随工作区保存。没有自动上传、后端、账户、统计埋点或付费 API。

## 评测边界

停车错例审查使用冻结模型的完整公开预测，按错误类型、摄像头和车位筛选，默认保留全部错例。车位漏判比例以该车位原始占用标签数为分母，不能用错例集中度推断原因。离线清单和本次浏览器推理分开：前者只提供定位及可复查来源；选择错例后，后者重新读取实际像素，读取失败保持未分析，不回填离线分数。

车位人工确认空闲/占用前，必须成功显示当前样本的原图；原图失败允许保存待复核或带理由的无法判断，导出单独记录证据读取失败。原图与模型输入是不同文件，因此两者的失败状态分开。导入历史人工记录不证明本次看过原图；如重新保存明确结论，同样检查当前原图。手机从错例跳转后定位选中车位和复核区，异步推理完成不得把用户后来选择的样本拉回。

固定合成班次比较逐条分数告警与场景规则队列，使用相同输入和分数门槛。匹配要求摄像头、区域、类别、轨迹相同，时间 IoU ≥ 0.1，按重叠从高到低一对一匹配。报告条目数、匹配、未匹配、漏检与紧急不确定项。

队列缩减不等于视觉精度提升或人工耗时降低。保留已知误报和没有观察输入的漏检。真实模型的运行烟雾测试与这套合成流程结果分开记录；公开图片和重复图片生成的短片不能证明社区领域准确率。
