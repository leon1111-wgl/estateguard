# 视频事件时间线 · MEVA 评测的预先固定协议

写于 2026-11-10，**在读取任何 MEVA 标签、计算任何分数之前**。此前只做过：读取已标注片段的名单（只有文件名）、对公开视频做 HTTP HEAD 取文件大小。变更须在本文件追加附录，不覆盖原文。

## 问题

0.5.0 给“视频与图片分析”加一个事件时间线：视频按固定频率采样，每帧跑现有检测器（D-FINE-N，不支持 SIMD 时 SSDLite），用本仓库的确定性跟踪器把检测连成轨迹，再用区域与停留规则把轨迹变成带起止时间的事件段。本协议回答：这三条规则在公开、带活动标注的监控视频上能对上多少真实活动，误报占用多少时间，以及失败主要来自哪里。

## 被评测的系统（代码见 `web/event-timeline.mjs`，评测与网页共用同一模块）

**采样与检测**
- 每秒 1 帧；评测取第 k 帧为解码帧号 n = k·round(fps)，时间 n/fps；每段最多 300 帧（5 分钟）。
- 画面按网页规则缩放（宽 ≤ 960、高 ≤ 1920）。MEVA 视频是 AVI 容器，Chromium 不能解码，所以评测由 ffmpeg 抽帧并双线性缩放，再交给网页同一个 `web/detector-dfine.mjs`（ONNX Runtime Web 单线程 WASM）。这一步与网页的浏览器解码不是同一路径，记为已知差异。
- 每帧最多 50 个检测，保留分数 ≥ 0.25 的检测（`detection_floor`）。

**跟踪器（固定，不在开发半上调）**
- 两阶段贪心关联（ByteTrack 思路）：先用分数 ≥ `minimum_score` 的检测，再用 0.25–`minimum_score` 之间的低分检测去接续仍未匹配的轨迹；只有高分检测能开新轨迹。
- 相似度：与“由最近两个采样做匀速外推”的预测框的 IoU（≥ 0.1）；IoU 不足时，若中心距离 < 1.5 个框尺寸且尺寸比在 0.5–2 之间，按距离给一个低于 0.1 的分数。距离以画面高度为单位（宽方向乘以宽高比）。
- 同组才能关联：car / truck / bus 一组，backpack / handbag / suitcase 一组，其余按类别本身。轨迹 2 秒内没有匹配即结束。并列时按轨迹创建顺序、再按检测顺序，结果确定。

**三条规则（全部只用轨迹和检测框，没有学习的行为分类器）**

| 规则 | 条件 | 事件段（参与评分的起止） | 关键帧 | 置信度 |
| --- | --- | --- | --- | --- |
| `vehicle_stop` 车辆停下 | car / truck / bus / motorcycle 轨迹：静止段（之后每个采样的中心都在起点 0.1 个框尺寸内）持续 ≥ `dwell_seconds`，且静止段之前的 3 步内有一步移动 ≥ 0.25 个框尺寸/秒；静止段起点在区域内 | 最后一个移动采样 → 确认停留的采样 | 静止段起点 | 静止段起点到确认采样的平均检测分数 |
| `object_left` 物品遗留（代理） | backpack / handbag / suitcase 轨迹：静止且无人员框覆盖（人员框盖住物品面积 > 10% 算有人看管）持续 ≥ `dwell_seconds`；该段必须是“新开始”的（物品在片段中途出现，或之前被搬动 / 被人员覆盖）；第一帧就在原处的物品不算 | 前一个采样帧 → 确认采样 | 段起点 | 同上 |
| `person_appears` 人员在门口出现 | 人员轨迹至少 2 个采样；第一个采样不在第一帧、中心在区域内、框不碰画面边缘（距边 1%） | 前一个采样帧 → 第 2 个采样 | 第一个采样 | 前两个采样的平均检测分数 |

事件段只覆盖“条件由假变真并被确认”的那一小段；之后持续多久另记为 `condition_seconds`，不进入评分。这样做是因为 ActEV 的时间误报会把一辆停了 4 分钟的车整段算成误报时间，而 MEVA 标注的是“停下”这个动作。

**区域**：评测对所有规则用整幅画面。MEVA 的摄像头没有独立于标签的通道、门口或禁停区划定；用标签反推区域会泄漏测试信息。因此 `person_appears` 只能靠“离画面边缘有距离”区分门口出现与从画面外走入，这是评测条件比现场更难的一处。

## 指标（ActEV 风格）

按 NIST《ActEV Sequestered Data Leaderboard Evaluation Plan》（Phase 3，2021-08-03）第 6、6.1、6.5 节，由本仓库 `scripts/actev-score.mjs` 重新实现，不是 NIST 的 ActEV_Scorer，结果称“ActEV 风格”：
- **时间误报** Tfa = Σ max(0, S′(t) − R′(t)) / NR：S′、R′ 为时刻 t 正在进行的系统 / 参考实例数，NR 为不被任何参考实例覆盖的时长；按区间精确计算，跨片段相加。
- **对齐**：参考实例 ≥ 1 秒时需重叠 ≥ 1 秒，否则需重叠其长度的 50%；匈牙利算法一对一对齐，偏向高置信度。
- **Pmiss@Tfa = x**：首个 Tfa 之前为 1.0，点间线性插值，最后一点之后取最小值。报告 x = 0.02（DIVA 计划的排名指标）与 0.1。
- **nAUDC@0.2**：Tfa 0–0.2 上 Pmiss 曲线下的归一化面积（SDL 排行榜主指标）；越低越好。
- **时间 IoU**：全部事件（不截置信度）时，已对齐对的交并比，报告均值、中位数与 ≥ 0.5 的个数。
- 另报全部事件时的 Pmiss（附 Wilson 95% 区间）、Tfa、未对齐事件数与每分钟未对齐事件数。
- 每条规则只与对应活动的参考实例比较；参考实例起点超出分析范围的不计，跨出的截断到分析末尾。

## 开发半上的选择（唯一调参）

- 网格：`minimum_score` ∈ {0.4, 0.5, 0.6} × `dwell_seconds` ∈ {2, 3, 4}。跟踪器和其余常数按上文固定。
- 选择：三条规则 nAUDC@0.2 的平均值最低者（只平均开发半上有参考实例的规则）；并列时取更高的 `minimum_score`，再取更长的 `dwell_seconds`。
- 选出的两个数写入 `web/event-timeline.mjs` 的 `TIMELINE_SETTINGS`（即网页默认值），单独提交，然后才运行测试半。

## 测试半

- 只评分冻结的这一组设置，只运行一次。首次结果连同提交号、运行号报告；之后的任何修改都不再是盲测，须另行标注。
- 无论结果如何都公开全部数字。若某条规则在测试半上全部事件时的 Pmiss ≥ 0.9，页面在该规则旁写明“在公开测试中几乎全部漏报”。时间线功能仍上线，因为它只产生线索，并且页面写明它看不到什么。

## 失败模式（在选定 / 冻结的设置下报告）

- **远处小人**：所有带人员标注的采样帧上，人员框按原图高度分桶（< 50、50–100、100–200、≥ 200 像素），统计是否有人员检测（分数 ≥ `minimum_score`）与之 IoU ≥ 0.3。
- **非 COCO 包裹**：`person_puts_down_object` 中非人员参与者的标注类型，以及放下后 5 秒内的采样帧上是否有 backpack / handbag / suitcase 检测与之 IoU ≥ 0.1。
- **轨迹换号**：人员与车辆参与者在采样帧上按 IoU ≥ 0.3 对应到轨迹；对至少有 3 个对应采样的参与者，报告平均对应到的不同轨迹数与换号次数（每 100 个对应采样）。

## 耗时预算

先做一次只跑检测、不读标签的耗时测量（开发半第 1 段）。若单段在一个作业里超过 8 分钟，测试半减为按同一顺序的前 12 段；这一决定只看耗时。开发 8 段、测试 16 段分别在 4 个并行作业里运行。

## 不在范围内

- 不训练、不微调任何模型；不使用视觉语言模型。
- 不评估夜间、红外、无人机视频，也不评估网页上的浏览器解码路径（由发布巡查与探针覆盖，不计分）。
- 结论只说明这三条规则在 MEVA 这一个设施的地面摄像头上的表现，不代表任何小区现场。
